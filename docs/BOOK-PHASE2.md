## 2.2 หนังสือเวียน — รายชื่อผู้รับ, การเวียน

**อ้างอิง 2546:** หนังสือเวียนราชการ  
**สถานะ:** implemented — รอ UAT

### ปัญหา / ช่องว่าง

- v1 รองรับส่งหนังสือเขต↔โรงเรียนและตอบรับ แต่ยังไม่มี workflow **เวียนหลายผู้รับ** แบบหนังสือเวียนราชการ
- ทะเบียนส่งมีประเภท ป/ว/อ แล้ว (Phase 1) — แต่โมดูล `book` ยังไม่ผูกการเวียนกับรายชื่อผู้รับเป็นชุด
- Legacy มีตารางที่เกี่ยวข้อง (`book_sendto_answer`, กลุ่มผู้รับ) — schema ใหม่มี `book_recipients` แล้ว แต่ UI/flow เวียนยังไม่ครบ

### ขอบเขตที่ต้องตัดสินใจ

- รายชื่อผู้รับ: เลือกจากบุคลากร / กลุ่มงาน / กลุ่มหนังสือ (`book_groups`) / โรงเรียนทั้งหมด?
- สถานะการเวียน: ใครรับแล้ว / ยังไม่รับ / ส่งต่อต่อ — แสดงที่ไหน (inbox ผู้รับ vs รายงานผู้ส่ง)
- ความสัมพันธ์กับโมดูล `mail` (P100 หนังสือเวียนไปรษณีย์) — แยกหรือรวม flow?

### งานหลัก (แผน)

1. สำรวจ flow PHP (`../Amssplus/modules/book`) — หน้าสร้างเวียน, รายชื่อผู้รับ, ตอบรับเวียน
2. ออกแบบ UI: สร้างหนังสือเวียน → เลือกผู้รับหลายราย → ติดตามสถานะ
3. API + บันทึก `book_recipients` ครบสถานะ
4. รายงาน / กรอง: หนังสือเวียนที่ยังไม่ครบการรับทราบ
5. ทดสอบเทียบ amsscnt.com + เพิ่มหัวข้อใน `TESTING-MODULES.md#book`

### เกณฑ์ done

- สร้างหนังสือเวียนพร้อมรายชื่อผู้รับได้
- ผู้รับเห็นใน inbox และตอบรับ/ส่งต่อได้
- ผู้ส่งเห็นสถานะรายผู้รับ
- Responsive + สิทธิ์ลับ (ถ้าเป็นหนังสือลับ)

## 2.3 ส่งค่าความเร็ว/ความลับจริงเมื่อสร้างจากทะเบียนหรือส่งต่อ

**อ้างอิง 2546:** ควบคุมหนังสือลับ/ด่วน  
**สถานะ:** implemented — รอ UAT

### ปัญหา / ช่องว่าง

- Phase 1 ทะเบียนรับ/ส่ง มี `urgency_level` และ `secret_level` ครบแล้ว
- เมื่อส่งต่อจากทะเบียนเข้า `book_main` / สร้างหนังสือจากทะเบียน — legacy บังคับ `level=1`, `secret=0` ในบาง path; ระบบใหม่ต้อง **ส่งค่าจริงจากทะเบียน**
- คอลัมน์ `forwarded_to_schools` ในทะเบียนส่งมีแล้ว แต่ integration ส่งต่อโรงเรียน/โมดูล `book` ยังไม่ส่ง metadata ความเร็ว/ลับ

### ขอบเขตที่ต้องตัดสินใจ

- Mapping: `register_*` → `book_documents.urgency_level` / `secret_level`
- สิทธิ์: ผู้ที่ไม่มี `can_view_secret` ต้องไม่เห็นหนังสือลับที่ส่งต่อมา
- กรณีส่งต่อหลายขั้น — คงระดับลับ/เร่งหรือลดได้หรือไม่ (เทียบ 2546 + PHP)

### งานหลัก (แผน)

1. ระบุจุดสร้างหนังสือจากทะเบียน / ปุ่มส่งต่อใน UI ทะเบียน
2. ส่งผ่าน service เดียว — ไม่ hardcode default ใน action
3. ทดสอบ matrix: ปกติ/ด่วน × ลับ 0–3 × เขต/โรงเรียน
4. อัปเดต checklist 2.3 ใน context เมื่อทดสอบผ่าน

### เกณฑ์ done

- สร้างหนังสือจากทะเบียนรับ/ส่ง → ความเร็วและความลับตรงต้นทาง
- ส่งต่อ → ค่าเดิมไม่ถูก reset เป็น 0/1 โดยไม่ตั้งใจ
- กรองรายการตามสิทธิ์ลับทำงานครบ

## 2.4 รูปแบบหน้าหนังสือ (คำลงท้าย, ลายเซ็น, ประทับตรา)

**อ้างอิง 2546:** แบบหนังสือราชการ  
**สถานะ:** implemented — รอ UAT

### ปัญหา / ช่องว่าง

- v1 เน้น workflow รับส่งและแนบไฟล์ — ยังไม่มี **แบบหน้าหนังสือราชการ** สำหรับพิมพ์/PDF ตามระเบียบ
- ทะเบียนมีแบบพิมพ์ทะเบียน (Phase 1.9) แล้ว — แยกจากแบบหน้าหนังสือออก

### ขอบเขตที่ต้องตัดสินใจ (ถามผู้ใช้เขต)

- คำลงท้ายมาตรฐานของ สพป.ชัยนาท (ชื่อตำแหน่ง, ลายเซ็นดิจิทัลหรือรูป)
- ประทับตรา: รูปภาพตายตัว / อัปโหลดต่อหนังสือ / ไม่ใช้ใน v2
- ช่องทาง output: พิมพ์จาก browser / generate PDF server-side
- ประเภทหนังสือ (ป/ว/อ/ประทับตรา) — แม่แบบต่างกันหรือไม่

### งานหลัก (แผน)

1. รวบรวมตัวอย่างหนังสือจริงจากเขต + ระเบียบ 2546
2. ออกแบบ template (HTML print หรือ PDF engine)
3. ผูกข้อมูลจาก `book_documents` + ตั้งค่าเขต (ชื่อหน่วย, เลขที่)
4. หน้าพิมพ์/ดาวน์โหลดจากรายละเอียดหนังสือ
5. ทดสอบกับหนังสือลับ (watermark / ข้อความข้อจำกัด)

### เกณฑ์ done

- พิมพ์หนังสือออกได้ตรงแบบที่เขตยอมรับ
- คำลงท้ายและลายเซ็นถูกต้องตามบทบาทผู้ลงนาม
- ใช้ได้บน mobile (อย่างน้อย preview + พิมพ์จาก desktop)

## 2.5 เชื่อมทะเบียนอัตโนมัติ (`book_link`, `record_type`)

**อ้างอิง 2546:** ทะเบียนเข้า–ออก  
**สถานะ:** implemented — รอ UAT

### ปัญหา / ช่องว่าง

- Schema มี `record_type`, `book_link` ใน `register_receives` + import จาก legacy แล้ว
- Phase 1.5 แสดงแหล่ง `book_link` ในทะเบียนรับเมื่อมาจากโมดูล `book` — **ทิศทาง book → ทะเบียน** ยังไม่ automatic ครบ
- ต้องการ: เมื่อลงรับ/ส่งใน `book` → สร้างหรืออัปเดตทะเบียนรับ/ส่งโดยอัตโนมัติ (หรือตามนโยบายเขต) พร้อม cross-link

### ขอบเขตที่ต้องตัดสินใจ

- Auto-create ทุกหนังสือหรือเฉพาะประเภท/ระดับ?
- เลขทะเบียน: ออกเลขทันทีหรือรอผู้ใช้ยืนยัน
- โรงเรียน: ทะเบียน `_sch` เดิมรวมเป็นตารางเดียว + `school_id` — mapping ตอนเชื่อม
- หนังสือที่แก้ไขหลังเชื่อม — sync หรือแยก snapshot

### งานหลัก (แผน)

1. นิยาม state machine: หนังสือ `book` สถานะใด → สร้างทะเบียนรับ/ส่ง
2. Service `RegistryLinkService` (ชื่อ working) — transaction + เลขทะเบียน (`RegistryNumberService` มีแล้ว)
3. UI: แสดงลิงก์สองทาง ทะเบียน ↔ หนังสือ
4. Import ข้อมูลเก่า: backfill `book_link` ที่มีใน legacy
5. ทดสอบ regression ทะเบียนที่ไม่มีหนังสือคู่ (external)

### เกณฑ์ done

- สร้างหนังสือจาก workflow ที่กำหนด → ทะเบียนถูกสร้างพร้อม `book_link` / `record_type` ถูกต้อง
- เปิดจากทะเบียนไปหนังสือต้นทางได้
- ไม่ duplicate เลขทะเบียนเมื่อ retry

## 2.6 อายุเก็บ / ทำลายเอกสาร (นโยบายเขต)

**อ้างอิง 2546:** การจัดเก็บ  
**สถานะ:** implemented — รอ UAT

### ปัญหา / ช่องว่าง

- v1 มีรายงานหนังสืออายุเกิน 2 ปี (`/modules/book/inbox/aged`) — เป็น **แจ้งเตือน** ไม่ใช่นโยบายเก็บ/ทำลายครบ
- ยังไม่มี workflow อนุมัติทำลาย, บันทึกวันทำลาย, หรือ retention ตามประเภทเอกสาร

### ขอบเขตที่ต้องตัดสินใจ (ถามผู้ใช้เขต)

- อายุเก็บต่อประเภท: หนังสือราชการ / คำสั่ง / หนังสือลับ — ตามระเบียบเขตหรือ 2546 อย่างเดียว
- ทำลาย = soft delete + ซ่อนจากผู้ใช้ หรือลบไฟล์ PDF จริง
- สิทธิ์: เฉพาะ admin สารบรรณ / คณะกรรมการทำลายเอกสาร
- รายงานก่อนทำลาย (ทะเบียน + รับส่ง)

### งานหลัก (แผน)

1. เก็บนโยบาย retention เป็นตั้งค่าเขต (ปีต่อ `document_type` หรือ `record_type`)
2. Job รายวัน/รายสัปดาห์: รายการครบอายุเก็บ
3. Workflow: ร่างรายการทำลาย → อนุมัติ → execute (audit log)
4. ผูกกับ PDF storage — ไม่ลบไฟล์ที่ยังอ้างอิงในทะเบียน
5. หน้ารายงานสำหรับตรวจสอบภายหลัง

### เกณฑ์ done

- ตั้งค่าอายุเก็บได้
- ระบบแจ้งรายการครบกำหนด
- ทำลาย (หรือปิดใช้งานถาวร) มี audit trail
- สอดคล้องนโยบายที่เขตยืนยัน — ไม่ขัด 2546
